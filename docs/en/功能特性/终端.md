# Terminal

FileCat's terminal is a purpose-built virtual terminal ([pty-shell](https://www.npmjs.com/package/pty-shell)), not the system bash or PowerShell. That gives the same experience on Windows and Linux, and lets it **check permissions before a command runs**.

## Step 1: grant command permissions (the usual stumbling block)

Only `pwd` and `ls` are allowed by default. **Any other command fails with a permission error** — that is by design, not a bug.

1. Open **Settings → Environment**
2. Find the command permission settings
3. Grant the commands you need, one by one
4. `*` allows every command

Because it parses commands itself instead of relying on regex matching, the check is trustworthy — a sub-account running `rm -rf /` is genuinely blocked.

> Grant only what an account needs. Don't take the `*` shortcut in production.

## Setting the PATH

Environment variables aren't configurable yet, but **PATH** is:

1. Open **Settings → Environment**
2. Find **Environment directories**
3. Enter the PATH entries

If `node` or `git` suddenly reports "command not found", check here first.

## Custom command validation

Beyond per-command grants, you can write validation code:

1. Open **Settings → Environment**
2. Find **shell command validation**
3. Write logic that decides whether a command and its arguments may run

More flexible than listing commands manually — for example "only allow read-only git subcommands".

## Commands that need a PTY

A PTY is the bridge between the terminal and the system shell. Many programs need one to learn the current screen size.

By default FileCat runs commands as plain child processes (**no PTY**). Some programs misbehave without one — most notably **recent versions of npm**.

To fix that:

1. Open **Settings**
2. Find **PTY CMD**
3. Add the commands that need a PTY, e.g. `npm`
4. Multiple entries are allowed

## No pipes, no `&&`

`|`, `&&` and `||` are **not supported** — only single commands.

The practical consequence: `grep` is unusable as-is.

**Workaround**: run `bash` (or `pwsh`) first, then type piping commands inside that shell, because pipes are handled by the shell itself.

## Closing the terminal kills child processes

Closing a terminal tab **kills every process started from it**, including nested children.

So don't launch long-running services from this terminal — they die with it. Use systemd or a background task for persistent services.

## Keyboard shortcuts

| Action | Notes |
| --- | --- |
| `Ctrl + C` | Interrupt the current command |
| `Ctrl + V` | Paste |
| `Tab` | Command completion |

## Multiple terminals

Open several sessions at once and arrange them in a grid — handy for watching multiple machines or comparing output side by side.

## Terminal vs. SSH manager

- **Terminal** — operates **this** server, the one running FileCat
- **SSH manager** — stores credentials for remote servers and connects to **other** machines

Use the SSH manager to manage a fleet of Linux boxes; use the terminal for the local host.
