# Mounts

Attach remote storage to FileCat and browse it like a local directory.

## Two concepts to get right

Configuration is split in two halves, and mixing them up is the usual cause of an empty folder:

- **Credential** — how to connect: host, port, username, password
- **Mount** — where to attach it: share name, bucket name, starting directory

One credential can back several mounts. Three shared folders on the same NAS need one credential and three mounts.

Order matters: **create the credential first, then the mount**.

## Mounting SMB (Windows share / Synology / NAS)

**Step 1: create a credential**

1. Open **Settings → Mounts → Credentials**
2. Choose type `SMB`
3. Enter the host, e.g. `192.168.x.x` or `nas.local`
4. Enter username and password
5. Save

**Step 2: create a mount**

1. Switch to the **Mounts** tab
2. Choose type `SMB` and select the credential you just made
3. Set **Location** to the **share name**, e.g. `share`
4. Save, then return to the Files page

> **Location** is a share name, not a path. To go into a subdirectory write `share/docs`.
> Do **not** write a Windows path like `\\192.168.x.x\share`, and do not prefix with `/`.

## Mounting S3 object storage

**Credential** needs: EndPoint (e.g. `https://oss-cn-hangzhou.aliyuncs.com`), AccessKey, SecretKey, Region.

**Location** is the **bucket name**, e.g. `my-bucket`. To limit to a prefix write `my-bucket/photos`.

Compatible with MinIO, Alibaba OSS, Qiniu and any S3-compatible store. If your provider requires path-style access, enable that switch in the credential.

## Mounting SFTP

**Credential**: host, port (default 22), username, and either password or private key.

**Location** is the remote starting directory; `/` means the root.

Good for connecting another Linux server. If the other side also runs FileCat, enable **File Services → SFTP** there and mount it here over SFTP.

## Mounting WebDAV

**Credential**: the full URL (e.g. `https://dav.example.com/remote.php/dav/files/user`), username, password.

**Location** is the starting directory, usually `/`.

Nextcloud and Jianguoyun both speak this protocol.

## Mounting Baidu Netdisk

Complete the OAuth flow in the credential: FileCat redirects you to Baidu's login page and fills in the token after authorisation.

Tokens expire after a while and must be re-authorised. If you get an authentication error, first check whether the token on the credential page has expired.

## Mounting another local directory

Useful for exposing server paths that fall outside your root directory.

Choose the **Local directory** mount type and leave **Location** empty — the source is determined by the account bound to the credential, where you specify the actual path.

## The mounted directory is empty

Work through these in order:

1. **Wrong Location** — the most common cause. SMB takes a share name (no backslashes, no leading slash); S3 takes a bucket name
2. **Network unreachable** — test with `telnet host port` from the server
3. **Insufficient permissions** — try an account with read/write access
4. **Config changed but not applied** — normally a config change rebuilds the connection automatically; if not, save the mount again

## Do I need to reconnect after changing config?

No.

FileCat caches driver instances keyed by mount plus a configuration fingerprint. When a credential or mount changes, the fingerprint changes, the cache is invalidated and the connection rebuilt.

## Mounts vs. file services

| | Mounts | File services |
| --- | --- | --- |
| Direction | Pull external storage **in** | Push local directories **out** |
| Who connects | FileCat connects out | Others connect to FileCat |
| Where to configure | Settings → Mounts | Settings → File Services |

To connect two FileCat instances, either side works: mount from one, or enable a file service on the other.
