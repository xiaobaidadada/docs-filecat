# File Services

Expose FileCat's directories outward so other devices can reach them over standard protocols.

The opposite of Mounts: mounts pull other storage in, file services push your directories out.

## Serving WebDAV

The most common case — both Windows and macOS can map it directly.

1. Open **Settings → File Services**
2. Choose **WebDAV**
3. Set the **listening port**, e.g. `8080`
4. Pick the **shared directory**
5. Set a **username and password** (without these it is anonymous — never do that on the internet)
6. Save and start
7. **Open the port in the firewall**

**Windows**: This PC → Map network drive → enter `http://server-ip:8080` → sign in.

**macOS**: Finder → Go → Connect to Server → enter `http://server-ip:8080`.

## Serving SMB

Browse like a shared folder on the LAN.

1. **Settings → File Services** → choose **SMB**
2. Set the port (default 445 — **change it, the default collides easily**)
3. Pick the directory and account
4. Save and start

Access it from Windows via `\\server-ip\`.

> Port 445 needs administrator rights on some systems and may already be taken by the built-in SMB server. A high port is simpler.

## Serving SFTP

For SSH clients, or as a mount source for another FileCat.

1. Choose **SFTP**
2. Set the port (default 22 — change it if sshd already owns it)
3. Pick the directory and account
4. Start

FileZilla and WinSCP can both connect.

## Serving FTP

For older devices, such as cameras that can only upload over FTP.

Same steps: choose FTP, set the port, pick the directory and account, start.

## Exchanging files between two FileCat instances

**Option 1 (recommended)**: enable SFTP on machine A → mount it over SFTP from machine B.

**Option 2**: enable WebDAV on A → mount it over WebDAV from B.

Either gives you read-write access both ways.

## Troubleshooting

**Connected but the directory is empty**
Check the shared directory path, and whether the user running FileCat can read it.

**Windows says it cannot access the share**
Confirm the firewall allows the port. Windows also blocks plain-HTTP WebDAV by default — set the `BasicAuthLevel` registry value to 2, or use HTTPS.

**Port already in use**
445 for SMB and 22 for SFTP are the usual culprits. If startup fails, pick another port rather than fighting for it.

## Security advice

- **Always set credentials**, especially when exposing to the internet
- Avoid default ports like 22 and 445 — scanners try them first
- Share only the directories you need; never expose `/`
- Prefer WebDAV over HTTPS on the public internet
