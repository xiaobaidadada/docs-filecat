# File Sync

Synchronise directories between two FileCat instances over a direct TCP connection.

## Sync is one-way

Data flows from the **sync source** to the **receiver**. For two-way sync, configure two rules in opposite directions.

## Step 1: start the service on the receiver

1. On the **machine receiving files**, open **Settings → Sync → Receiver**
2. Set the **listening port**, e.g. `9100`
3. Set an **authentication token**
4. Save and start
5. **Open the port in the firewall**

## Step 2: configure the source

1. On the **machine providing files**, open **Settings → Sync → Source**
2. Enter the receiver's **IP and port**
3. Enter the **token** (must match the receiver)
4. Save

## Step 3: add a sync task

Add a task on the source:

| Field | What to enter |
| --- | --- |
| Local directory | The source directory, e.g. `/data/www` |
| Remote directory | The target on the receiver, e.g. `/backup/www` |

Save and start the task.

## A note on first sync

The first run transfers **everything** in the source directory. For large directories over the internet this is slow, so:

1. Complete the initial sync on the LAN
2. Then move the machine or switch to the internet
3. Only changes are transferred afterwards

## Troubleshooting

**Cannot connect to the receiver**
Test the port with `telnet receiver-ip 9100` first. If it fails, it is the firewall or the service isn't started.

**Token error**
Both tokens must match exactly — watch for stray whitespace.

**Files missing after sync**
Check whether the user running FileCat can read every file in the source; files it cannot read are skipped.
