# Command Line

FileCat can be configured through command-line arguments or environment variables. Arguments take precedence over environment variables.

## Basic usage

```bash
# after a global npm install
filecat --port 5567 --base_folder /data/filecat

# running from source
node src/main/main.js --port 5567
```

## Common arguments

| Argument | Description | Default |
| --- | --- | --- |
| `--port` | Web server port | `5567` |
| `--hostname` | Bind address | `0.0.0.0` |
| `--base_folder` | Data root: database, logs, cache | see below |
| `--user_name` | Initial admin account | `admin` |
| `--password` | Initial admin password | randomly generated |
| `--lang` | Default UI language: `zh` / `en` / `sys` | `sys` |
| `--https_port` | HTTPS port | disabled |
| `--ssl_key` | Path to the SSL private key | — |
| `--ssl_cert` | Path to the SSL certificate | — |
| `--watch` | Watch files and reload on change (development) | off |

> `--lang sys` follows the browser language.

## The data directory

`--base_folder` decides where all persistent data lives, including:

- database files such as `data.json`
- temporary upload files
- logs
- the recycle bin, if configured in the default location

When running from source without specifying it, data usually lands in a `filecat-data` directory under the project.

> When migrating servers, copying the whole `base_folder` preserves everything.

## Environment variables

Every argument has an environment variable form: prefix `FILECAT_`, upper case, underscores.

For example:

```bash
# equivalent to --port 8080
export FILECAT_PORT=8080
```

Handy for Docker, systemd and other setups where editing the start script is inconvenient.

## Admin account on first run

You can set the admin credentials at first startup:

```bash
filecat --user_name admin --password yourpassword
```

If omitted, a random password is generated and printed to the console — check it promptly and change it.

> Credentials only take effect on **first initialization**. After that, change them through the UI.

## Development arguments

| Argument | Description |
| --- | --- |
| `--watch` | Watch source files and reload automatically; development only |

Do not enable this in production — the file watching adds unnecessary overhead.

## Checking the effective configuration

On startup the console prints the actual listening address and data directory. If a port conflict appears, first check whether another FileCat instance is already running.
