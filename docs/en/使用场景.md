# Use Cases

FileCat scales from "manage one machine" to "manage a fleet". Below are the typical shapes of deployment.

## Personal server management

The lightest setup: run FileCat on your own VPS or home server.

- Move files and edit configs in the browser, no FTP client needed
- Run commands in the embedded terminal with custom command filtering
- Watch CPU, memory and disk in real time, with almost no overhead
- Open huge log files instantly, with live tailing

## Home network access

You have a NAS, a router and a Windows PC at home, but no public IP.

- **Tunneling** exposes services to the internet
- **Virtual network** assigns each device a virtual IP, forming a virtual LAN
- **RDP** remote-controls Windows in the browser
- **Wake-on-LAN** wakes a sleeping machine

## Team file sharing

A single file server used by a team.

- **Multi-user with permission isolation** — each person sees only their own directories
- **File services** — LAN colleagues reach it through Windows network neighbourhood, no browser required
- **Audit log** — a record of who changed what and when
- **Recycle bin and protected paths** — deleted files can be recovered, critical directories cannot be deleted

## Automation builds

Use **Workflow** instead of a heavyweight tool like Jenkins.

- GitHub Actions-style YAML syntax
- Give any file the `.act` extension and run it from the context menu
- Supports `inputs`, `need-job` dependencies and interactive `repl` steps
- Remote trigger API for git hooks to kick off builds automatically

## Managing many servers

When you have a dozen remote Linux machines.

- **SSH manager** stores every machine's credentials; one click to log in
- File operations feel close to local, and you can edit code directly
- The terminal is the remote machine's own shell, so the environment matches exactly
- Combined with **tunneling**, you can also reach other devices on those machines' internal networks

## AI-assisted operations

Hand repetitive operations to AI.

- Describe what you want in plain language; the AI calls tools to do it
- Connect DingTalk / Lark / QQ bots to ask from a chat group
- Restrict the AI's tool permissions — start read-only, then widen

## Static asset distribution

Serve several directories as static sites.

- Mount any number of directories
- Built-in login control, can integrate with single sign-on
- Good for distributing installers, documentation and images
