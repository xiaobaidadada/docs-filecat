# 终端

FileCat 的终端是自研的虚拟终端（[pty-shell](https://www.npmjs.com/package/pty-shell)），不是直接调系统自带的 bash / powershell。好处是 Windows 和 Linux 上体验一致，并且**能在命令执行前判断权限**。

## 第一步：给命令授权（最容易卡住的地方）

默认只允许 `pwd` 和 `ls`，**其它命令一执行就是没权限**。这不是 bug，是设计。

1. 打开 **设置 → 环境**
2. 找到命令权限设置
3. 给需要的命令授权，多个命令分别添加
4. 填 `*` 表示允许所有命令

因为它自己解析命令，不靠正则过滤，所以权限判断可以完全信任 —— 子账号执行 `rm -rf /` 这类命令会被真正拦住。

> 想让某个账号能执行什么就配什么。生产环境别图省事直接给 `*`。

## 设置环境目录（PATH）

目前没有提供环境变量设置，但可以配置 **PATH**：

1. 打开 **设置 → 环境**
2. 找到「环境目录」
3. 填 PATH 路径

配错了会发现 `node`、`git` 这些命令提示找不到，先检查这里。

## 自定义命令校验

除了逐条授权，还能写校验代码：

1. 打开 **设置 → 环境**
2. 找到「shell 命令校验」
3. 写判断逻辑，决定某个命令和参数能不能执行

比手动列举更灵活，比如「只允许 git 的只读子命令」。

## 需要 PTY 的命令

PTY 是终端和系统 shell 之间的桥接层。很多命令需要它才能知道屏幕大小。

默认 FileCat 用子进程直接执行命令（**不开 PTY**）。某些命令在没 PTY 时会出问题，最典型的是 **npm 最新版**。

解决办法：

1. 打开 **设置**
2. 找到「PTY CMD」
3. 把需要 PTY 的命令加进去，比如 `npm`
4. 可以添加多条

## 管道和 && 不支持

目前**不支持** `|`、`&&`、`||` 这类操作，只能执行单个命令。

直接后果：`grep` 基本没法用。

**绕过办法**：先执行 `bash`（或 `pwsh`），进入那个 shell 之后再敲带管道的命令 —— 因为管道是在 shell 内部处理的。

## 关闭终端会杀掉子进程

关掉终端标签时，**所有从该终端启动的进程都会被杀死**，包括嵌套的子进程。

所以别在这个终端里启动需要长期运行的服务，进程会被一起带走。长期服务用 systemd 或后台任务。

## 快捷键

| 操作 | 说明 |
| --- | --- |
| `Ctrl + C` | 中断当前命令 |
| `Ctrl + V` | 粘贴 |
| `Tab` | 命令补全 |

## 多个终端

可以同时开多个会话，网格排列，方便同时盯多台机器或对比输出。

## 和 SSH 管理的区别

- **终端** —— 操作 FileCat 所在的**这台**服务器
- **SSH 管理** —— 保存多台远程服务器的账号，连到**其它**机器

管一批远程 Linux 用 SSH 管理，管本机用终端。
