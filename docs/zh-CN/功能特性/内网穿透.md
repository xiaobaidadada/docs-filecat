# 内网穿透

让没有公网 IP 的服务能被外网访问。

FileCat 内置了基于 FRP 的穿透，**服务端和客户端都是 FileCat**，不用单独部署 frps。

## 先分清两端

- **服务端** —— 装在**有公网 IP** 的机器上，接收外部连接
- **客户端** —— 装在**要暴露的内网机器**上，把本地服务上报给服务端

两台都要装 FileCat。搞反了方向就通不了。

## 第一步：配置服务端（公网机器）

1. 打开 **设置 → 穿透 → 服务端**
2. 设置**监听端口**，例如 `7000`（客户端会连这个端口）
3. 设置**认证 token**，随便一串够复杂的字符串
4. 保存并启动服务端
5. **在云厂商安全组 / 防火墙里放行这个端口**

> token 一定要设。不设的话任何人都能连上你的服务端，把你的流量转走。

## 第二步：配置客户端（内网机器）

1. 打开 **设置 → 穿透 → 客户端**
2. 填写**服务端地址**（公网机器的 IP 或域名）
3. 填写**服务端端口**（上一步设的 7000）
4. 填写**token**（必须和服务端完全一致）
5. 保存

## 第三步：添加转发规则

在客户端里加规则，告诉它要暴露什么：

| 字段 | 填什么 | 例子 |
| --- | --- | --- |
| 本地地址 | 要暴露的内网服务 | `127.0.0.1:8080` |
| 远端端口 | 外网访问用的端口 | `18080` |

保存后，外部访问 `公网IP:18080` 就等于访问内网的 `127.0.0.1:8080`。

> 远端端口也要在公网机器的防火墙上放行。

## 典型场景：家里的服务暴露出去

1. 云服务器装 FileCat，配服务端，放行 7000 和业务端口
2. 家里机器装 FileCat，配客户端指向云端
3. 加转发规则：本地 `192.168.x.x:5000`（NAS 管理页） → 远端 `15000`
4. 外网访问 `云服务器IP:15000` 就能进 NAS 后台

## 典型场景：访问内网设备

路由器的管理页面、内网 Windows 的远程桌面，都能这样穿透出去。

RDP 的话，本地地址填 `内网IP:3389`，远端端口自己定一个。

## P2P 直连模式

普通模式下，数据要经过服务端中转，受服务端带宽限制。

P2P 模式会尝试让两端直接打洞连接：

- 成功：数据不经过服务器，延迟低、带宽大
- 失败：自动回退到中转模式

打洞成功率取决于双方的 NAT 类型，对称型 NAT 通常打不通。

## 安全提醒

- **必须设 token**，这是底线
- 不要把数据库、Redis 这类敏感服务的端口暴露到公网
- 优先暴露 HTTPS 服务，别在公网上跑明文
- 可以配合 FileCat 的访问控制，限制来源 IP

## 通了但不稳定？

按顺序排查：

1. **防火墙** —— 服务端端口、远端端口都要放行，云厂商的安全组和系统防火墙是两套，都要改
2. **token 不一致** —— 客户端连不上服务端，先核对 token
3. **客户端和服务端版本差太多** —— 尽量用同一版本的 FileCat
4. **带宽** —— 中转模式受服务端出口带宽限制，大流量考虑 P2P
