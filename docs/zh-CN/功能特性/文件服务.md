# 文件服务

把 FileCat 的目录对外提供出去，其它设备用标准协议访问。

和「网盘挂载」方向相反：挂载是把别人的拉进来，文件服务是把自己的推出去。

## 开一个 WebDAV 服务

最常用的场景，Windows 和 macOS 都能直接挂载。

1. 打开 **设置 → 文件服务**
2. 选择 **WebDAV**
3. 设置**监听端口**，例如 `8080`
4. 指定**共享目录**（服务器上的哪个路径）
5. 设置**账号密码**（不设就是匿名访问，公网千万别这么干）
6. 保存并启动
7. **在防火墙上放行这个端口**

**Windows 挂载**：此电脑 → 映射网络驱动器 → 填 `http://服务器IP:8080` → 输入账号密码。

**macOS 挂载**：Finder → 前往 → 连接服务器 → 填 `http://服务器IP:8080`。

## 开一个 SMB 服务

局域网内像访问共享文件夹一样。

1. **设置 → 文件服务** → 选 **SMB**
2. 设置端口（默认 445，**改掉容易冲突的默认端口**）
3. 指定共享目录和账号
4. 保存并启动

Windows 里通过 `\\服务器IP\` 访问。

> 445 端口在某些系统上需要管理员权限，或者已被系统自带 SMB 占用。换一个高位端口更省事。

## 开一个 SFTP 服务

给 SSH 客户端用，也可以作为另一台 FileCat 的挂载源。

1. 选 **SFTP**
2. 设置端口（默认 22，如果服务器已有 sshd 占用就换一个）
3. 指定目录和账号
4. 启动

用 FileZilla、WinSCP 都能连。

## 开一个 FTP 服务

兼容老设备，比如只能 FTP 上传的摄像头。

配置方式同上：选 FTP、设端口、指定目录和账号、启动。

## 两台 FileCat 互传文件

**方案一（推荐）**：A 机器开 SFTP 文件服务 → B 机器用 SFTP 挂载连上。

**方案二**：A 机器开 WebDAV → B 机器用 WebDAV 挂载。

两种都能实现双向读写。

## 常见问题

**连上了但目录是空的**
检查共享目录路径是否填对，以及运行 FileCat 的用户是否有该目录的读权限。

**Windows 提示无法访问**
先确认防火墙放行了端口。另外 Windows 默认禁止用 HTTP 访问 WebDAV，需要改注册表 `BasicAuthLevel` 为 2，或者用 HTTPS。

**端口被占用**
SMB 的 445 和 SFTP 的 22 最容易被系统服务占用。启动失败时换一个端口，别硬抢。

## 安全建议

- **一定要设账号密码**，尤其是暴露到公网时
- 不要用 22 / 445 这些默认端口，扫描器第一时间就会试
- 只共享必要的目录，不要把 `/` 整个开出去
- 公网上优先走 WebDAV + HTTPS
