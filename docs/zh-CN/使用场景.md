# 使用场景

FileCat 的能力可以从「管一台机器」扩展到「管一批机器」，下面是典型的落地用法。

## 个人服务器管理

最轻量的用法：在自己的 VPS 或家用服务器上跑一个 FileCat。

- 网页里传文件、改配置，不用再开 FTP 客户端
- 内嵌终端敲命令，支持自定义命令过滤
- 实时看 CPU、内存、磁盘，几乎不占资源
- 大日志文件秒开查看，支持实时追加

## 家庭内网访问

家里有 NAS、路由器、Windows 主机，但没有公网 IP。

- 用 **内网穿透** 把服务暴露到公网
- 用 **虚拟网络** 给每台设备分配虚拟 IP，构成一个虚拟局域网
- 用 **RDP** 在浏览器里远程控制 Windows 主机
- 用 **网络唤醒** 把休眠的电脑叫醒

## 团队文件共享

一个团队共用一台文件服务器。

- **多用户 + 权限隔离** —— 每个人只能看到自己的目录
- **文件服务** —— 局域网同事用 Windows 网上邻居直接访问，不必开浏览器
- **操作日志** —— 谁在什么时候动了什么文件都有记录
- **回收站与保护路径** —— 误删能找回，关键目录禁止删除

## 自动化构建

用 **Workflow 工作流** 替代 Jenkins 这类重型工具。

- 采用 GitHub Actions 风格的 YAML 语法
- 对任意文件设置 `.act` 后缀，右键即可执行
- 支持 `inputs` 参数、`need-job` 依赖、`repl` 交互
- 可配置远程触发 API，配合 Git 钩子自动构建

## 统一管理多台服务器

手上有十几台远程 Linux 机器时。

- **SSH 管理** 保存所有机器账号，点击即登录
- 登录后文件操作体验接近本地，可直接编辑代码
- 终端使用远程机器自带 shell，环境完全一致
- 配合 **内网穿透** 还能访问这些机器所在内网的其它设备

## AI 辅助运维

把重复的运维工作交给 AI。

- 用自然语言描述需求，AI 调用工具完成
- 支持接入钉钉 / 飞书 / QQ 机器人，在群里直接提问
- 可限制 AI 的工具权限，先只读后放开

## 静态资源分发

把多个目录作为静态站点对外提供。

- 支持挂载任意多个目录
- 自带登录控制，可对接单点登录
- 适合分发安装包、文档、镜像等资源

## 受众群体

| 人群 | 典型诉求 |
| --- | --- |
| 个人开发者 | 单兵作战，需要运维 + 构建 + 监控全套工具 |
| 小团队 | 多人访问同一台服务器，需要权限隔离 |
| 公司内部 | 自动化构建、资源分发下载 |
| 家庭用户 | 远程访问内网设备、管理 NAS |
